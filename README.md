# StockSense Database

MySQL 8.0+ database for the StockSense Inventory Management System.

## 1. Architecture

The database follows the inventory flow defined by the StockSense requirements:

Product -> Inventory by Location -> Stock Documents -> Stock Ledger -> Alerts

Supported operations:
- Receipts / incoming goods
- Delivery orders / outgoing goods
- Internal transfers
- Inventory adjustments
- Multi-warehouse inventory
- Product categories
- Units of measure
- Reordering rules
- Low-stock and out-of-stock alerts
- Dashboard KPIs
- User authentication data
- OTP password reset
- Audit logging

## 2. Main tables

- `users`: application users and roles.
- `password_reset_otps`: OTP reset workflow.
- `categories`: product categories.
- `units_of_measure`: pcs, kg, m, box, etc.
- `products`: product master data and SKU.
- `suppliers`: vendors supplying stock.
- `warehouses`: physical warehouses.
- `locations`: racks, production, receiving, shipping and other stock locations.
- `inventory`: current quantity for each product/location pair.
- `reorder_rules`: minimum and reorder quantities.
- `stock_documents`: receipts, deliveries, transfers and adjustments.
- `stock_document_items`: products and quantities within documents.
- `stock_ledger`: immutable-style movement history used to audit stock changes.
- `alerts`: low-stock and out-of-stock notifications.
- `audit_logs`: application-level audit trail.

## 3. Important relationships

- One category has many products.
- One product can exist in many locations.
- One warehouse contains many locations.
- One supplier can be linked to many receipts.
- One stock document contains many document items.
- Every stock movement can be recorded in the stock ledger.
- Reorder rules are defined per product and location.

## 4. Installation

Run files in this order:

```text
1. schema.sql
2. indexes.sql
3. views.sql
4. procedures.sql
5. triggers.sql
6. seed.sql
```

Example:

```bash
mysql -u root -p < schema.sql
mysql -u root -p stocksense_db < indexes.sql
mysql -u root -p stocksense_db < views.sql
mysql -u root -p stocksense_db < procedures.sql
mysql -u root -p stocksense_db < triggers.sql
mysql -u root -p stocksense_db < seed.sql
```

## 11. Backend integration

The backend should connect using a restricted database user rather than the MySQL root account.

Example environment variables:

```env
DB_HOST=localhost
DB_PORT=3306
DB_NAME=stocksense_db
DB_USER=stocksense_app
DB_PASSWORD=change_this_password
```

Passwords must never be stored as plain text. `users.password_hash` is intended for a bcrypt/Argon2-style password hash generated by the backend.

## 12. Stock consistency

`inventory` stores the current stock snapshot.

`stock_ledger` stores stock movement history.

For production operations, stock changes should happen inside a database transaction so that the inventory update and ledger entry succeed or fail together.

## 13. Assumptions

The requirements specify inventory operations rather than a full sales/accounting system. Therefore, the MVP does not add unrelated entities such as customers, invoices, payments, purchase orders, accounting journals, or manufacturing bills of materials.

The `stock_documents` table provides a common structure for receipts, deliveries, internal transfers and adjustments.

For an internal transfer, both source and destination locations are required.

For a receipt, a supplier is required.

For a delivery, stock is reduced from the operational source location by the backend/service layer.

For an adjustment, the application should compare recorded quantity with the physical count and create the corresponding positive or negative ledger movement.

Authentication itself should be implemented by the backend; this database only stores the necessary user and OTP data.

## 14. Demo credentials

The seed file contains demonstration users with placeholder password hashes. Replace these hashes with real bcrypt/Argon2 hashes generated by the backend before using the application.
